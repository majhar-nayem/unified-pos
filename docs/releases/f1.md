## What landed

### Data access (`packages/db`)

- `runInTenantTransaction(pool, tenantId, fn)` — BEGIN → `SET LOCAL app.tenant_id` (verified via `platform.current_tenant()`) → fn → outbox append → audit append → COMMIT → `onCommitted` callbacks. `readInTenant` for read-only work. The `TenantScopedDb` handle is only constructible inside these and is closed after the transaction, so an escaped handle cannot run on a recycled connection.
- Audit hash chain: `canonicalJson` (sorted keys, safe integers only), `auditHash = sha256(prev ‖ canonical(row))`, per-tenant advisory lock on append, `audit.audit_chain_heads`, `verifyAuditChain` (streams by `seq`, reports the first broken seq and head mismatch). `ip` is excluded from the hash.
- Outbox and idempotency helpers; `grantAppRole()` grant matrix (SELECT-only on `platform.*` and `identity.permissions`, no UPDATE/DELETE on `audit.audit_log`, EXECUTE on the 0002 functions); `pnpm --filter @pos/db grants` for the compose stack; UUIDv7 ids.

### Migration 0002 (`packages/db/migrations/0002_f1_tenancy_identity_audit.sql`)

`version` columns on org units / legal entities / departments; closure trigger with a cycle guard; RLS on `identity.role_permissions` through `identity.roles`; role-tenant and scope-reference triggers; `tenancy.fn_scope_path(kind, id)`; SECURITY DEFINER functions for the outbox relay (with a 60 s claim lease and a dead-letter marker), idempotency purge, tenant provisioning and the access-catalog seed; passkey and refresh-rotation columns (`sign_count`, `transports`, `aaguid`, `backed_up`, `prev_refresh_token_hash`, `mfa_verified_at`, `amr`, `location_id`); one open business day per location.

**The migration role must be a superuser or hold BYPASSRLS** (asserted by `migrate()`): every tenant table FORCEs row level security, so SECURITY DEFINER bodies only cross tenants when their owner can.

### Shared packages

- `@pos/auth`: `can()` with validity windows, typed limits (number ≤, boolean, array containment, string), `requiresMfa()`, `mergeLimits()`, the permission catalog and nine system roles (`tenant_owner`, `admin`, `finance`, `store_manager`, `shift_supervisor`, `cashier`, `server`, `kitchen`, `readonly_auditor`). System-role default limits live in code, not in `permission_limits` (that table requires a tenant).
- `@pos/contracts`: tenancy, config (`CONFIG_KEYS` registry), identity, access, device and approval DTOs; event catalog additions.
- `@pos/domain-core`: `businessDate(instant, timezone, boundary)`.

### API kernel (`apps/api/src/modules/kernel`)

Request context (AsyncLocalStorage, correlation ids in every log line) → `AuthGuard` (token kinds, operators) → `ScopeGuard` (`x-scope` from the route contract, `fn_scope_path`, 404 when the principal reaches none of the ancestors) → `ContractInterceptor` (zod 4, 422 with issue trees, `If-Match` → 428/412) → `IdempotencyInterceptor` (two-phase, replay header, 409 in flight, 422 mismatch) → `EtagInterceptor` → handler; `GlobalExceptionFilter` maps pg 42501/23503/22P02 → 404, 23505 → 409, 23514 → 422 without leaking constraint names. `AuthorizationService.assert()` is called in services; `out_of_scope` → 404, missing permission → 403, exceeded limit → `LimitExceededError`. OpenAPI 3.1 at `GET /v1/openapi.json` from zod's native JSON Schema, with `x-scope`, `x-permission`, `x-public`, `x-operator`, `x-idempotent`, `x-fixture` and `$fixture:` examples that drive the harness.

Outbound ports (`KernelPorts`: authenticator, scope resolver, first-admin provisioner) are bound explicitly by `AppModule.onModuleInit`; tests rebind after `app.init()`. This replaced DI-token overrides, which a global module's own providers never see.

### Tenancy, platform, audit, worker

`/v1/tenants/me`, org units (+ reparent under a per-tenant advisory lock), legal entities, locations, departments, registers, `/v1/config` (nearest override + history + versioned writes), business days; `POST /v1/tenants` (operator-only, one transaction: tenant → root org unit → first admin → audit → `tenant.provisioned`); feature flags (nearest scope, 30 s cache). `/v1/audit`, `/v1/audit/head`, `POST /v1/audit/verify`. Worker: outbox relay to Redis Stream `pos:events` (dead letters to `pos:events:dead` after 10 attempts), consumer base with `processed_events` dedupe, hourly idempotency purge.

### Identity, access, devices

- Platform-native authentication: Argon2id (`@node-rs/argon2`, OWASP minimum), EdDSA JWTs (`jose`; ephemeral keys outside production, `pnpm --filter @pos/api auth:keygen` for real ones), AES-256-GCM sealed TOTP secrets, WebAuthn passkeys (`@simplewebauthn/server`), per-location PINs with Redis lockouts driven by `identity.pin.*` config keys, Ed25519 device enrolment (`<tenant-slug>.<code>`) and signed-challenge login, client credentials.
- Login state machine: bad password → `login_events` + counter (5/15 min → 423); password ok + roles with `*.admin`/`finance.*` → `mfa_required` (or `mfa_enrollment_required`) with a 5-minute `preauth` token; TOTP/passkey → full session with `mfa=true`. Refresh tokens rotate with reuse detection (`prev_refresh_token_hash`; reuse revokes the session). Device and API tokens are stateless and re-checked against `enrollment_status` / client status (60 s cache for devices).
- Token kinds and lifetimes: web 15 min (refresh 12 h sliding, 30 d absolute), pos 60 min (refresh 14 h, bound to the device), device 24 h, api 30 min, preauth 5 min. Claims: `sub tid knd sid did loc amr mfa av scp jti iat exp`.
- Access: catalog seeded at bootstrap through `identity.fn_seed_access_catalog`; system roles immutable (clone to customise); assignments with scope, validity window, reason, assignment-level limits; `av:{tenant}:{user}` Redis counter invalidates cached principals; approvals (request → approve with manager PIN / passkey / MFA session, approver must hold the underlying permission within their own limits, no self-approval, lazy 15-minute expiry, hash-checked consumption).
- Operators: no login flow yet; `AUTH_OPERATOR_TOKENS="operatorId:op_<secret>,…"` grants operator principals for provisioning until the IdP decision (plan §13).

### Passkey full ceremony

- `apps/api/src/testing/software-authenticator.ts`: a software WebAuthn authenticator for tests. One P-256 key from `node:crypto`, a minimal CBOR encoder, attestation object with `fmt: 'none'`, authenticator data (`rpIdHash ‖ flags UP|UV|AT ‖ counter ‖ aaguid ‖ credentialId ‖ COSE key`), `clientDataJSON`, DER ECDSA assertions. `assert(options, { counter })` replays a stale counter to simulate a cloned key.
- `identity/credentials/passkey.service.ts` `verifyAuthentication`: `@simplewebauthn/server` throws on a counter regression before the service could react, so the stored counter is withheld from the library and the regression check runs after signature verification, where the credential is revoked (the intent of the original code, which was unreachable).
- Tests added:
  - `apps/api/src/testing/software-authenticator.test.ts` — "encodes CBOR heads for every integer width and negative ints"; "completes registration and authentication; the counter advances; a stale counter is rejected by the library".
  - `apps/api/src/identity.integration.test.ts` — "passkey full ceremony with a software authenticator: register, log in with mfa_required → passkey, counter advances, a stale sign count revokes the credential" (options → malformed 422 → challenge consumed 409 → fresh options → 201 with `transports`/label/credential id stored → login returns `mfa_required` with `methods: ['totp', 'passkey']` → `POST /v1/auth/mfa/passkey/options` + `/verify` → authenticated session with `mfaVerified` → replayed challenge 401 → second sign-in advances `sign_count` → stale counter: 401 `MFA_FAILED`, credential `revoked`, options 409 `PASSKEY_NOT_ENROLLED`, login offers TOTP only, `login_events` show `success, success, mfa_failed`). The previous passkey/password-reset test was split; the reset part is now "admin password reset revokes sessions and the old password stops working".

### Rate limiting (pipeline step 1)

- `apps/api/src/modules/kernel/rate-limit/`: `token-bucket.ts` (pure `takeToken()` plus the equivalent Lua script Redis runs atomically per key), `rate-limit.config.ts` (`RATE_LIMIT_CONFIG` token, env parsing with defaults, `RATE_LIMIT_DISABLED` for tests), `rate-limit.guard.ts` (`RateLimitGuard`, `rateLimitSubject()`).
- Registered in `app.module.ts` as the first global guard, ahead of `AuthGuard`. Both guards share one authentication per request through `kernel/auth/authenticate-once.ts`, so the limiter can key authenticated callers by `tenant:kind:subject` (operators by operator id) and everything else, including bad tokens, by client IP.
- Behaviour: `X-RateLimit-Limit` / `X-RateLimit-Remaining` on every limited response; 429 `RATE_LIMITED` with `Retry-After` (seconds, ≥ 1) and `details.retryAfterSeconds` when the bucket is empty. When Redis is unavailable, `pos` and `device` tokens pass with a warning log (fail open); every other caller gets 429 `RATE_LIMITER_UNAVAILABLE` with `Retry-After: 1` (fail closed). `TooManyRequestsError` (429) joined the kernel errors.
- Env (`.env.example`): `RATE_LIMIT_ENABLED` (true), `RATE_LIMIT_CAPACITY` (300 burst) / `RATE_LIMIT_REFILL_PER_SECOND` (100) per principal, `RATE_LIMIT_PUBLIC_CAPACITY` (60) / `RATE_LIMIT_PUBLIC_REFILL_PER_SECOND` (10) per IP, optional `RATE_LIMIT_KEY_PREFIX`. Invalid values fail at boot.
- `createTestApp()` disables the limiter unless `rateLimit` is given and accepts a `redisClient` (used to simulate an outage); `userPrincipal()` now returns `TenantPrincipal` so tests can set `tokenKind`.
- Tests added:
  - `apps/api/src/modules/kernel/rate-limit/token-bucket.test.ts` — "a fresh bucket is full and the first take leaves capacity - 1"; "drains to zero, then refuses with the time until one token refills"; "refills proportionally to elapsed time and never beyond capacity"; "a cost above capacity is never allowed and reports the full refill time"; "the key TTL covers a full refill plus a second of slack"; "uses the documented defaults when nothing is set"; "reads every RATE_LIMIT_* variable"; "rejects zero, negative, non-numeric and non-boolean values at boot"; "anonymous requests share one bucket per IP and fail closed"; "tenant principals are keyed by tenant + kind + subject; pos and device tokens fail open"; "operators are keyed by operator id".
  - `apps/api/src/rate-limit.integration.test.ts` (postgres + redis containers) — "an authenticated principal gets `capacity` requests, then 429 with Retry-After, then refills"; "anonymous and badly authenticated requests share one bucket per IP"; "with Redis unavailable, web tokens fail closed (429) and POS tokens fail open".
- Not done: per-client limits from `identity.api_clients.rate_limit_per_minute` (the principal does not carry it yet) and WebSocket/sync traffic.

### Drizzle schema diff-check (Sprint 0 exit criterion)

- `packages/db/src/schema-check.ts`: `mirroredTables()` (every `PgTable` exported from `src/schema`, via `getTableConfig`), `introspectLiveSchema()` (`information_schema.columns`, types normalised to Drizzle's `getSQLType()` spelling: arrays, `citext`, `char(n)`, `numeric(p,s)`, `timestamp`/`time` without zone), pure `diffSchema()` and `checkSchemaMirror()`. Reports missing tables, missing or unmirrored columns, type, nullability and default-presence mismatches.
