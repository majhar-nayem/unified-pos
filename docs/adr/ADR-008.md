# ADR-008: Tauri 2 for POS/KDS; React Native for handheld (Phase 3)

- Status: **Accepted, hardware spike required** (risk R1; Sprint 0 go/no-go)
- Decision area: client technology
- Related: [01 §1, §15 R1](../01-system-architecture.md), [03 §4 Hardware spike, §12](../03-implementation-plan.md), [operations/supported-devices.md](../operations/supported-devices.md), [ADR-019](ADR-019.md)

## Context

POS and KDS need native hardware access (ESC/POS over USB and network, cash drawer kick, HID scanners, Bluetooth scales, customer display second window) and a local encrypted SQLite store, on Windows and Android first, then macOS/iOS. The team is React/TypeScript. The Payments Edge must run as a native plugin on a register (ADR-019). Binary size and memory on low-cost Android tablets matter.

## Decision

POS and KDS are React apps in **Tauri 2** (webview shell with Rust plugins for hardware, SQLCipher storage, keychain access and the Payments Edge) on Windows, Android, macOS and iOS. The handheld app (line busting, stock counts) is React Native in Phase 3. Admin is Next.js. Native code is limited to plugins where hardware or security demands it.

The decision is conditional on the Sprint 0 hardware spike (R1): Tauri 2 on Windows and Android must drive ESC/POS USB and network printing, drawer kick, HID scanner and Bluetooth scale. Fallbacks, documented in advance: Store Hub-owned printing, then an Electron shell for desktop (risk table, plan §12).

## Alternatives considered

1. **Electron (desktop) + React Native (mobile).** Fallback; heavier runtime, two UI stacks.
2. **Flutter.** Rejected: second language and no reuse of `domain-core` without bridging.
3. **Native per platform.** Rejected: team size.
4. **PWA only.** Rejected: no reliable USB/serial/Bluetooth, no native Edge for terminals, storage eviction risk offline.

## Consequences

- Positive: one UI skill set; small footprint; Rust plugin boundary suits secrets and PCI-adjacent code.
- Negative: Tauri mobile plugin ecosystem is younger; Android USB host and Bluetooth plugins may need to be written; webview version variance by OS (Android System WebView, WebView2, WKWebView) means a minimum-OS policy ([supported-devices](../operations/supported-devices.md) §1).
- Security: auto-updater with signed bundles, staged rollout and kill-switch pin (plan §10); certificate pinning with rotation plan (architecture §11); local DB encrypted with key in OS keychain/Keystore.
