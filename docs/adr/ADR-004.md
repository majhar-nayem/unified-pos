# ADR-004: Money as bigint minor units; tax persisted per line

- Status: **Accepted**
- Decision area: money and tax representation
- Related: [01 §1, §7.2](../01-system-architecture.md), [02-database-design.md](../02-database-design.md), [ADR-005](ADR-005.md), [ADR-013](ADR-013.md), [03 §5 F3](../03-implementation-plan.md)

## Context

Retail and hospitality totals must reconcile to the cent across receipt, payment, refund, settlement and accounting export. Floating-point drift, inconsistent rounding and tax recomputed later with changed rules all create disputes. Australian cash rounding (5c) applies to the cash tender only. Multiple tax rates, inclusive and exclusive pricing, and proportional discount allocation must sum exactly.

## Decision

- Amounts are `bigint` in minor units with an ISO 4217 currency code alongside; currency precision is configuration. Rates and quantities that need fractions (`quantity numeric(14,4)` for shared items, tax rates) use `numeric`. No floating point in any financial path.
- Discount allocation uses the largest-remainder method so allocated parts equal the whole.
- Tax is computed once, at pricing time, by `domain-core`, and **persisted per order line** (`order_line_taxes`) with the rule, rate and inclusive/exclusive mode that produced it. Receipts, reports, refunds and exports read the persisted rows; they never recompute tax.
- Rounding for cash is applied only to the tender and recorded as `rounding_minor`.
- In TypeScript, money is a branded integer type with a small library; JSON contracts carry integers (safe-integer range enforced; the audit canonicaliser also accepts safe integers only).

## Alternatives considered

1. **`numeric(12,2)` money columns.** Rejected: scale is per column not per currency, easy to mix scales, JS clients still need integer arithmetic.
2. **Compute tax on read.** Rejected: a rule change would silently alter historical receipts and refunds; auditors need the as-sold tax.
3. **Decimal library in the client.** Rejected: slower, harder to keep byte-identical between server and device than integers.

## Consequences

- Positive: exact reconciliation, reproducible refunds (a return line references the original line's persisted tax), byte-identical results between server and offline device with the golden files (ADR-005).
- Negative: schema stores more rows; migrating a currency with a different exponent is a data operation, not a config flip.
- Fraud link: persisted per-line amounts make discount abuse and refund-above-original detectable by joins ([threat model](../security/threat-model.md)).
