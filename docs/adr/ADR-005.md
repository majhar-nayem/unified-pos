# ADR-005: `domain-core` shared TypeScript engine for pricing, tax, promotions and state machines

- Status: **Accepted**; engine delivered by stream S-F3 (price engine) and S-F2 (tax)
- Decision area: calculation engine placement
- Related: [01 §1, §7.2](../01-system-architecture.md), [03 §5 F3, §9, §15.1](../03-implementation-plan.md), [ADR-004](ADR-004.md), [ADR-009](ADR-009.md), [ADR-018](ADR-018.md)

## Context

Offline checkout needs totals the customer can be charged against. If the device estimates and the server later recalculates differently, every difference becomes a dispute or a sync conflict (risk R5). Pricing is also needed in the admin console (promotion preview) and in tests.

## Decision

Pricing, tax, promotions, order totals, rounding, allocation and state machines live in one pure TypeScript package, `packages/domain-core`, with no I/O. The same `priceOrder()` runs in the API, the worker, the POS client (including offline) and the admin preview. JSON golden files (input → totals plus ordered rule trace) are the executable specification; the same files run in server CI and inside the POS app build; any diff fails CI. Test gates: 100 % of money paths covered, mutation score ≥ 85 % (plan §9).

On sync the server re-executes the command through the normal application service and recomputes; a mismatch becomes `sync_conflict` of kind `pricing_mismatch`. Policy: honour the price the customer paid and record the delta. Configuration version is carried in every command payload so drift is explainable.

## Alternatives considered

1. **Server-only pricing with client estimates.** Rejected: estimates are not what is charged offline; disagreements surface at sync time as money problems.
2. **Re-implement per client (Kotlin/Swift/Rust).** Rejected: multiple engines diverge; golden files would have to be ported and policed.

## Consequences

- Positive: offline totals identical to online totals by construction; one place to fix a rounding bug; admin preview equals POS behaviour.
- Negative: the engine's runtime constraints (no Node-only APIs, bundle size, deterministic ordering) bind every change; key-person risk (plan §12) mitigated by pairing and golden files.
- Security link: client-side execution means a tampered client can compute any total; the server re-pricing on sync and approval limits are the controls ([threat model](../security/threat-model.md), "offline tampering" and "discount abuse").
