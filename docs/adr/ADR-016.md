# ADR-016: AWS ap-southeast-2, ECS Fargate, Terraform

- Status: **Accepted**; EKS if sidecar or mesh needs appear
- Decision area: hosting and delivery
- Related: [01 §1, §4, §12](../01-system-architecture.md), [03 §4 Infra baseline, §10](../03-implementation-plan.md), [ADR-001](ADR-001.md), [ADR-015](ADR-015.md)

## Context

Australia is the first market; data residency by region is required from day one (architecture R9). The team is small and the system has few long-lived processes (`api`, `worker`, `payments`). RPO/RTO targets: Phase 1 5 min / 4 h (restore), Phase 3 5 min / 1 h (warm standby in a second region).

## Decision

Run in AWS `ap-southeast-2` (Sydney): ECS Fargate for `api`, `worker` and `payments` (separate tasks, IAM roles and DB roles), Aurora PostgreSQL multi-AZ, ElastiCache Redis, S3 with SSE-KMS (Object Lock for audit anchors), Secrets Manager and KMS, CloudFront + WAF + ALB at the edge. Infrastructure as code in Terraform (`infra/**`, S-INFRA); GitHub Actions deploys through OIDC to a deploy role (no long-lived keys). Blue/green deploys with canary and automatic rollback on SLO burn; migrations expand-only. Additional regions are separate region-pinned deployments, not a single global cluster.

## Alternatives considered

1. **EKS.** Rejected for v1: cluster operations overhead; reconsider if sidecars/mesh are needed.
2. **GCP.** Rejected: team and procurement familiarity with AWS; Sydney region exists on both, no decisive technical difference found.
3. **Serverless-first.** Rejected, see ADR-001.

## Consequences

- Positive: managed building blocks; residency satisfied; the Terraform baseline gives the `dev` environment from CI in Sprint 0.
- Negative: Fargate lacks host-level control; Aurora cost at idle for preview environments (ephemeral preview envs use scaled-down resources).
- Security: infra defines IAM boundaries on which several mitigations depend (payments role isolation, KMS key policies, Object Lock anchoring, WAF rules); each is listed with an owning slice in the [threat model](../security/threat-model.md).
